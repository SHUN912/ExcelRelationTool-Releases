# ExcelRelationTool

用于应收整理、营收统计、交车锁车核查、区域汇报及周度经营简报更新的 Excel 桌面工具，提供 Windows 和 macOS 安装包。

本仓库用于发布正式安装包、版本更新说明及软件更新信息。

**[下载正式版](https://github.com/SHUN912/ExcelRelationTool-Releases/releases/latest)** · **[查看历史版本](https://github.com/SHUN912/ExcelRelationTool-Releases/releases)**

## 功能一览

| 功能 | 用途 |
| --- | --- |
| 功能一：生成总表与汇总 | 整理账单与费用数据，结合公共资料、区域及费用映射生成应收总表与汇总；支持为指定账单设置字段值。 |
| 功能二：生成分类报表 | 根据应收表填写整体、各项类型和经销商模板；经销商其他费用可随费用类型映射动态拆分。 |
| 功能三：营收数据统计报表 | 汇总营收数据，生成整体、经销商分区域、经销商分类型、自营门店分区域及目标与实际营收报表。 |
| 功能四：每日交车锁车检查情况 | 核查交车车辆在过去一个月的锁车检查情况；连续日期交车表可按天拆分，分别输出每日结果及中间文件，并提示零交车日期。 |
| 功能五：经营报表更新 | 整理交车、收车、车辆明细等数据，更新经营情况表，并保留处理过程的中间结果。 |
| 功能六：区域汇报底稿 | 利用经营情况表和已处理的车辆明细、交车、收车表，按门店区域填写上月底稿中的车辆数量、交收车及营收版块。 |
| 功能七：周度经营简报更新 | 根据区域运营日报，填写周度经营简报中的全国车辆数及自营门店、经销商、行业客户实际数据，保留模板中的目标及上月实际数据。 |

具体可用功能、输入字段和处理规则以安装版本的界面提示及对应 Release 说明为准。

## 下载与安装

前往 **[Releases](https://github.com/SHUN912/ExcelRelationTool-Releases/releases)**，在目标正式版本的附件中选择对应平台的安装包。

| 平台 | 安装包 | 安装方式 |
| --- | --- | --- |
| Windows | Windows 安装程序（`.exe`） | 运行安装程序，按可见安装向导完成安装。 |
| macOS · Apple Silicon | Mac Apple Silicon 安装映像（`.dmg`） | 打开 DMG，将 `ExcelRelationTool.app` 拖入 Applications；升级时选择替换原应用。 |

- 正式安装包包含软件所需的 Python 运行依赖，无需自行安装 Python。
- 涉及 Excel 联动、数据透视表等处理时，需要安装桌面版 Microsoft Excel；仅有网页版 Office 不能替代本地 Excel。
- 系统最低版本、芯片架构及其他兼容要求以对应 Release 说明为准。Mac `arm64` 安装包面向 Apple Silicon，不作为 Intel Mac 安装包使用。

## 开始使用

1. 根据要使用的功能准备输入表格。文件名中的日期用于识别业务时间和生成输出名称，请保留正确的日期时间戳。
2. 在公共资料中维护大客户表、应收底稿和经销商清单，并检查各功能需要的映射与模板。
3. 上传文件，确认软件识别的文件、月份、区域及输出设置，然后开始处理。
4. 处理完成后打开输出文件夹，查看最终报表；需要核查数据时，查看对应的中间文件和运行日志。

常用衔接流程：

- **应收与营收：** 功能一 → 功能二 → 功能三。功能三可使用本次软件会话中功能一或功能二最近一次成功输出的应收表。
- **经营与区域汇报：** 功能五 → 功能六。功能五完成后可继续执行功能六，带入相关结果，再补充上月区域汇报底稿。
- **每日核查：** 功能四可独立执行。连续日期输入会分别生成每日结果；单日输入继续按单日处理。
- **周度经营简报：** 功能七独立执行，使用区域运营日报和周度经营简报模板，无需先运行功能一至六。

## 功能七：周度经营简报更新

### 准备文件

- **输入文件：** 一份区域运营日报，文件名须包含“运营日报”，并带有数据对应日期。
- **日期格式：** 支持 8 位 `YYYYMMDD` 或 6 位 `YYMMDD`，月份、日期不足两位时补 `0`。例如 `区域运营日报20261018.xlsx` 或 `区域运营日报261018.xlsx`。
- **报表模板：** 将公司内部提供的模板放入功能七的模板文件夹，文件名包含“周度经营简报模板”；同一文件夹只保留本次使用的一份，可通过界面入口打开文件夹或预览模板。

### 处理与输出

1. 上传区域运营日报，确认日期及区域映射。
2. 检查模板；月初只需更新目标及上月实际数据，确认完成后在软件中标记已更新。
3. 选择输出文件夹，开始处理。软件按日报填写全国、自营门店、经销商和行业客户版块的实际数据。
4. 完成后查看最终简报；需要追溯来源时，查看中间结果和运行日志。

全国版块的车辆数“实际”取日报“运营车辆数”的求和；自营门店及经销商按对应区域汇总，行业客户按运营组织类型识别。模板中的 `YYYY/MM/DD` 日期占位符会替换为四位年份的完整日期，例如 `2026/10/18`。

功能七只更新本次实际数据及日期，不代替用户维护目标和上月实际数据。重跑历史数据时，可按界面提示暂不确认本月模板更新。

## 模板、映射与公共资料

- **公共资料：** 大客户表、应收底稿和经销商清单由用户维护。请按实际业务及时更新，并在软件中确认资料状态。
- **区域与门店：** 门店变动时，在功能一的映射设置中维护区域与签约门店对应关系；功能六会结合映射和底稿 Sheet 确认区域对应。
- **费用分类：** 费用类型增减时，同步检查费用分类映射和相关模板。
- **报表模板：** 由公司内部人员提供，请按各功能的界面提示放入对应文件夹。软件升级不代表用户模板自动完成月度更新；需要换月或调整布局时，请先检查模板。

## 检查更新

在正式版中使用 **“检查更新”** 获取已发布的新版本，并按提示完成下载、校验及安装。

- 可以直接从旧版升级到最新版，无需逐版安装。
- 支持历史更新日志的版本，会按当前安装版本筛选尚未安装的正式版本，并在更新提示中按版本分组显示，可滚动查看。
- 历史日志暂时无法完整取得时，软件会提示，并保留最新版本说明和正常更新入口。
- 已安装的旧客户端不会因 GitHub 更新说明文件变更而自动获得新界面能力；相关能力需安装支持它的版本后才生效。

更新使用完整安装包替换程序代码。当前正式版将用户映射与安装程序分开存放，已有用户设置不会被新版默认映射直接覆盖；新增配置及旧格式兼容情况以版本说明为准。原始业务文件和已生成报表不会因为更新而自动重新处理。

如需回退，可从历史 Release 下载对应安装包。新旧版本的数据规则可能不同，回退前请保留当前配置和输出备份。

## 输出与问题反馈

各功能会按业务日期组织最终文件、中间结果和运行日志。程序报错或结果不符合预期时，建议提供：

- 软件版本、操作系统及使用的功能；
- 报错截图和本次运行日志；
- 预期结果与实际结果的具体差异；必要时附脱敏样例。

请勿在公开 Issue 中上传未脱敏的客户名称、合同、账单、车架号、车牌或其他业务资料。
